## 启动后端（`npm start` / 8787），顺手修了 5 个只有真跑才暴露的问题

宝宝说「启动后端」。`npm start` = `node server/ai-proxy.mjs`，一个端口同时提供 `dist` 页面和全部 `/api`，所以前端不用另起（`npm run dev` 才是 Vite + 代理那套）。前面用 `vite preview` 只是静态托管，拍照 OCR 与 AI 审查都打不通。

**实测环境**：`/api/health` → provider DeepSeek / ocrMode offline-tesseract / hasApiKey true。`.env` 里只有 `AI_PROXY_ALLOWED_ORIGIN` 和 `DEEPSEEK_API_KEY` 两项。

### 1. 同端口访问时静态资源全被 CORS 拦（500）

`allowedOrigins` 只有 `localhost:5173 / 127.0.0.1:5173`。vite 给 script/link 加了 `crossorigin`，浏览器把这些静态请求也当 CORS 请求，Origin = `http://127.0.0.1:8787`，不在白名单 → `cors()` 抛错 → 500，页面白、样式加载不了。

修：`server/config.mjs` 自动把 `http://localhost:<port>`、`http://127.0.0.1:<port>` 并进白名单。这是「单端口模式」的必需项，不是本地特例。

### 2. OCR 成功一次后，整个 Node 进程猝死

现象：`/api/ocr/image` 返回 200（216 字、置信度 92），几百毫秒后服务没了，`/api/health` 连不上。

stderr 只有：
```
libpng warning: IDAT: Extra compressed data
Error: Error attempting to read image.
    at Worker.<anonymous> (tesseract.js/src/createWorker.js:217:15)
  process.nextTick(() => { throw err; })
```
根因：`createWorker(langs, oem, options)` 的 `options.errorHandler` 没传，库只能 `throw`，而它发生在 `nextTick` 里，不归属任何请求，直接带走进程。

修（`server/services/ocr.mjs`）：传 `errorHandler` 收集错误；`worker.terminate()` 加 `.catch`（识别已成功，不能因收尾失败打成 500）；文本为空且有 worker 错误时抛出带原因的异常。另在 `ai-proxy.mjs` 的 `isMainModule` 分支加了 `unhandledRejection` / `uncaughtException` 只记日志不退出。

守门：新增 `tests/unit/ocr-worker.test.mjs`（4 组：errorHandler 必须注册、异步错误不抛、terminate 失败不影响结果、空结果带原因），已进 `test:unit` 链。

### 3. `/api/ai/smoke` 的 OCR 自检永远失败——样本图自己是坏的

`SMOKE_PNG_FIXTURE` 是手写字节的 1x1 PNG，IDAT 的 CRC 是错的，leptonica 报 `IDAT: CRC error / no pix returned`，于是 smoke 一直报 `ocr.success: false`，看起来像 OCR 坏了。用 zlib + crc32 重新生成一张合法 1x1 PNG，改成 base64 常量。现在 smoke 两项都 true（AI 1392ms / OCR 903ms）。

### 4. OCR 把千分位逗号读成点，月租 2,800 变成 2.8

图片测试包的基准是「2,800元」，OCR 输出「2.800 元」。`contractFacts.js` 的 `digits = Number(raw.replace(/[^\d.]/g,''))` 直接得 2.8，确认页显示月租 2.8 元。

修：`/^\d{1,3}(?:\.\d{3})+$/` 命中时按千分位剥离点，否则保留小数（`1.2 万元` 不受影响）。`contract-facts.test.mjs` 加一组 OCR 写法断言。

### 5. 结论句把违约金说成「租金调整」，损失卡把「算不出」说成「没读到月租」

- `late-fee` 在 CAT_RULES 里归「租金调整」大类，于是结论写「其中租金调整条款可能让你多损失 ——」，和卡片标题「逾期违约金标准可能过高」对不上。新增 `catLabelOf()`：只有 cat 是租金调整且 id 命中违约金家族时才叫「违约金」，分类本身不动。`amountEngine.computeVerdict` 改用 `top.catLabel || top.cat`。
- 违约金这类没有可定价机制的风险，`amountForRisk` 返回 `kind: 'none'`，原来会拼出「多损失 —。」。现在单独一句「它没有固定金额，实际损失取决于真出事时怎么算」。
- 损失卡「待补」的说明原来一律说「没读到月租或押金」。但这份合同月租押金都读到了（2800/2800），失败原因是条款本身不能折算。`OverviewTab` 收 `hasAmounts`，三种情形分开：没有必须改的条款 → `—` + 「不需要估算损失」；缺数 → 「补上就能算」；有数但算不出 → 「这几条没有固定金额可以折算」。单测钉死结论句里不能出现 `—` 或 `待补`。
