## 追问：为什么有风险「未匹配到具体法条」（只诊断，未改代码）
用户截图问「未匹配到具体法条」的原因。查清是**设计断层，不是 bug**，四环连锁：
1. `createAiReviewPrompt`（aiAssistant.js:263-281）的 JSON schema 根本没有法条字段，第 287 行硬性要求「只返回上述精简字段，不额外生成法律条文」——模型被明确禁止给法条。
2. 所以 `normalizeAiFindings`（aiAssistant.js:181）对每条 AI finding 只能塞兜底文案「建议结合《民法典》合同编及相关司法裁判规则复核。」——截图那句就是它。
3. 唯一补法条的 `enrichFindingsWithLegalBasis`（contractReview.js:436）靠 `canLinkLegalBasis` 逐字证据匹配（≥8字、evidence 互相包含）。AI 补盲发现的本就是本地规则没覆盖的条款，本地无同句 finding 可继承 → 继承不到。
4. 法条表 `LEGAL_BASIS_MAP`（51 条）的 key 是本地 finding id（如 `lease-termination-asymmetry`），AI 风险带的是 playbookId（标准卡 id 如 `early-termination-loss`），**两套 id 体系对不上**，无法按卡继承。9 张标准卡全部无对应法条映射。

结论：规则引擎命中的风险有法条（实测 3 条都有）；AI 补盲的风险一律无具体法条，显示兜底是刻意诚实、不编造。
修复方向（未做，等用户定）：给 9 张标准卡配可核实法条映射，AI 风险按 playbookId 继承；或放宽 prompt 让模型给法条（与「不编造」原则冲突，不推荐）。

## 追问「还是没有法条」——方案 A 实测未生效，两个真 bug（本轮修复）
用户再次截图：AI 补盲风险仍显示「未匹配到具体法条 · 建议结合《民法典》…」（兜底文案来自 aiAssistant.js:181）。dist 时间(10:57)晚于源码(10:55)、playbookLegal 已打包——排除构建/缓存问题。

用 `scripts/diag-ai-legal.mjs`（打 8787 /api/ai/chat，复用前端同款 prompt/parse/enrich）抓真实 AI 输出：合成合同 8 条 finding 全部补上了法条 → 方案 A 逻辑本身能跑。再写 `diag-repro.mjs` 复现用户场景，锁定两个 bug：
1. **幻觉 playbookId 短路推断（核心）**：`enrichFindingsWithLegalBasis` 用 `finding.playbookId || getPlaybookIdForFinding(finding)`——AI 给一个非空但无效/幻觉/本地 id（如 `lease-bogus-id`、`risk-9`）时，`||` 短路掉推断，查表落空→无法条。明明能从 title 推断出卡却因假 id 白丢。实测：幻觉 id + 标题含违约金，旧代码 legalLaw=空。
2. **推断只看 title 不看 evidence**：`getPlaybookIdForFinding` 仅匹配 title，AI 标题常泛化（「费用计算不合理」），推断落空。evidence 是逐字原文含实词，此前完全没用上。

修复：
- `contractReview.js#enrichFindingsWithLegalBasis`：`legalForPlaybook(finding.playbookId) || legalForPlaybook(getPlaybookIdForFinding(finding))`——先验证 id 真在映射表，不在就退回推断，不短路。
- `contractReviewPlaybook.js#getPlaybookIdForFinding`：evidence 纳入推断（`text = title + evidence`）；补充关键词——多倍/占用费/逾期搬离归违约卡、入户/换锁/腾退优先、费用卡加「收取费用/收费/杂费/费用计算」。注意优先级：特定卡先于泛卡，避免 evidence 里的「押金」把违约/入户抢成押金卡。
- `tests/unit/playbook-legal.test.mjs` 加回归 #8（幻觉 id 不短路）、#9（泛标题结合 evidence 推断）。
- 验证：两复现脚本三场景全部补上法条；真实 AI 诊断 8/8 条命中；全套单测 exit 0；rm -rf dist 重建（11:14）；E2E 21 步 exit 0；git 无误删。诊断脚本已删除（临时）。
- **残留诚实边界**：#8「未尽事宜由甲方最终解释」被 AI 自己错标 deposit-settlement，补了押金法条（错配）。标准卡体系无「格式条款」卡，理想应留空；这是 AI 给错 id 所致，非本次「未匹配」bug，属按卡继承的粗粒度代价（已标注不当法律意见）。
