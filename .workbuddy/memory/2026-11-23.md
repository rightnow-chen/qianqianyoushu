## 追问：为什么有风险「未匹配到具体法条」（只诊断，未改代码）
用户截图问「未匹配到具体法条」的原因。查清是**设计断层，不是 bug**，四环连锁：
1. `createAiReviewPrompt`（aiAssistant.js:263-281）的 JSON schema 根本没有法条字段，第 287 行硬性要求「只返回上述精简字段，不额外生成法律条文」——模型被明确禁止给法条。
2. 所以 `normalizeAiFindings`（aiAssistant.js:181）对每条 AI finding 只能塞兜底文案「建议结合《民法典》合同编及相关司法裁判规则复核。」——截图那句就是它。
3. 唯一补法条的 `enrichFindingsWithLegalBasis`（contractReview.js:436）靠 `canLinkLegalBasis` 逐字证据匹配（≥8字、evidence 互相包含）。AI 补盲发现的本就是本地规则没覆盖的条款，本地无同句 finding 可继承 → 继承不到。
4. 法条表 `LEGAL_BASIS_MAP`（51 条）的 key 是本地 finding id（如 `lease-termination-asymmetry`），AI 风险带的是 playbookId（标准卡 id 如 `early-termination-loss`），**两套 id 体系对不上**，无法按卡继承。9 张标准卡全部无对应法条映射。

结论：规则引擎命中的风险有法条（实测 3 条都有）；AI 补盲的风险一律无具体法条，显示兜底是刻意诚实、不编造。
修复方向（未做，等用户定）：给 9 张标准卡配可核实法条映射，AI 风险按 playbookId 继承；或放宽 prompt 让模型给法条（与「不编造」原则冲突，不推荐）。
