## 质检页按来源分派语义（commit 50c5179）

用户看截图提出：**直接传 PDF 为什么会有「文字识别率 第 2 页 61%」「反光区域集中在押金条款」？识别率不是只有拍照才需要吗？**——完全正确。

- **根因**：`UploadScreen` 是原型阶段的静态文案，数字全写死（`21 处文字层缺失`、`第 2 页 61%`、`反光`、`第 4 条 · 押金`、`低置信度 2 处`），传任何文件都长一样。而且左右自相矛盾：缩略图每页打勾「文字层完整」，标题却写「21 处缺失」；标题「共 2 页」、下面「其余 3 页 96%」。
- **修法**：新建 `features/uploadQuality.js`（从 App.jsx 整体迁出，因为 App 是 JSX，Node 测不了），按 `source` 分派 `mode = ocr | text | plain`，返回结构化 `checks / advice / previewText / footerHint`；`UploadScreen` 改为纯数据驱动。
- **产品判断（关键，别反悔）**：质检屏**不删**，但语义按来源换。
  - PDF / Word：质检 = 「提取对不对」，给一段提取预览让人扫一眼有没有多栏串行；文案是「自带文字层，逐字提取，不经过 OCR，没有识别损耗」。
  - 图片 OCR：质检 = 「识别准不准」，才有识别率、反光、重拍、补救办法。
  - TXT / 粘贴：没有页的概念，不编页数。
  - 逐页缩略图只在拍照、或确实有坏页时渲染——22 页文件铺 22 个打勾方块只是噪音。
- **顺带修的两个真 bug**：`countMasked` 手机号正则缺前后边界，18 位身份证里的 11 位子串被算成手机号（2 个身份证报成「3 个手机号」）；PDF 页数改用 `pdf.numPages`，不再拿字数估。
- **守门**：`tests/unit/upload-quality.test.mjs` 8 组，PDF 与纯文本两组显式断言文案里**不出现**「识别率 / 反光 / 重拍 / 置信度」。单测 11 → 12 个。
- 门禁：lint 零告警 / build / 12 个单测 / e2e 14 步 / verify:mvp 12/12。

## 修 P0：用户上传 PDF 直接报错（`hashOriginal.toHex is not a function`）

用户实测时贴了截图：拖文件进来立刻弹这句英文，文件根本传不上。

- **根因**：`pdfjs-dist@6.2.108` 的**标准构建**在 worker 里调 `Uint8Array.prototype.toHex`（ES2026 新方法，Chrome/Edge 133+ 才有），标准构建里**没有任何 polyfill**；legacy 构建才有（`toHex: function toHex()`）。用户的浏览器内核低于 133（360 / QQ / 微信内置 / 旧 Edge 都常见）→ 计算文档指纹第一步就崩。
- **修法**：`src/utils/fileImport.js` 改引 `pdfjs-dist/legacy/build/pdf.worker.mjs?url` + `pdfjs-dist/legacy/build/pdf.mjs`。代码零改动，代价 worker 1.6MB→2.4MB。
- **验证陷阱**：`page.addInitScript` 删 `Uint8Array.prototype.toHex` **测不出来**——它只作用于页面主线程，而 toHex 在 worker 线程调用，worker 仍是 Playwright 自带新版 Chromium 的原生实现。所以改成静态断言，见下。
- **守门**：新增 `tests/unit/contract-import.test.mjs` 7 组，第 5–7 组分别断言源码引用、`node_modules` 的 legacy worker、`dist` 产物三处都不能退回标准构建；若官方将来补了 polyfill，第 6 组会打印提示。
- **顺带修两件**：
  - 新增 `ContractImportError`：底层库异常一律收敛成中文人话（按 PDF/Word/图片给不同下一步动作），原始异常只 `console.error`。之前 `toast(error.message)` 会把技术栈信息直接弹给应届生用户。
  - 扫描件 PDF 没有文字层 → 抽出的正文 <30 个汉字/字母时直接提示改用拍照 OCR，不再让空合同走进确认页。
- 一次性冒烟脚本 `scripts/verify/pdf-upload-smoke.mjs`（起服务 → 上传 qhd 真实 PDF → 等 toast）。
- 门禁：lint 零告警 / build / 11 个单测 / e2e 14 步 / verify:mvp 12/12。
- **踩到的构建坑**：`vite preview` 正在服务 `dist` 时，`vite build` 清空 `dist/assets` 会失败（safe-delete shim 报 `Some operations were aborted`）。顺序必须是：先停 preview → `rm -rf dist` → build → 再起 preview。

## 确认页（P2）改造：显示用户上传的原件 + 修金额 bug

用户实测提了三条：① 传任何文件左边都是示例合同；② 月租/押金「识别错误」（显示 280/560）；③ PDF/Word 能不能直接显示上传的文档。外加两处要删的废话和面包屑。

- **左侧预览**：新建 `features/filePreview.js`（按来源分派 previewKind / 渲染 PDF 页 / objectURL）+ `screens/confirm/PaperPreview.jsx`。PDF 用 pdfjs legacy 渲染**真实页面到 canvas**（可翻页），图片显示原图，Word 用 mammoth 的 structure 还原标题/段落/列表并明说排版无法还原，TXT/粘贴显示全文。`session.rawFile` / `session.structure` 承载原始文件。
- **金额「识别错误」两个根因**：
  1. 显示裁剪——`.field input` 宽 64px 且 flex-shrink 默认 1，5 位数被挤掉左侧（13500 显示成 600）→ 改 80px + `flex: 0 0 auto` + tabular-nums。
  2. **真 bug**：`AMOUNT_RE` 用 `\d+`，合同写「4,500 元」只匹配到 500，押金 13,500 → 500。改成 `\d[\d,]*`，并补「万元 → 元」换算。真实样本恰好不带逗号，所以一直没暴露。
- **读不到就明说**：rent/deposit/months 为 0 时字段黄底高亮 + 提示「月租、押金没读出来，请手动填」，不再让人以为是算错。
- **删掉**：确认页面包屑（新建审查·上传与质检·确认基础信息·看结果）、「不用选模板、不用挑规则…」tip-panel、「只做审查范围的确认…」hint。
- **e2e 第 15 步**：真实上传 22 页 PDF，断言 canvas 存在且**真的画上了像素**（采样非白点数），并断言「原件/识别全文」两个切换按钮。
- **坑**：e2e 自带静态服务器的 MIME 表漏了 `.mjs`，pdf.js worker 拿不到 JS，上传后静默无反应。线上部署同样要确认 `.mjs` 返回 text/javascript。
