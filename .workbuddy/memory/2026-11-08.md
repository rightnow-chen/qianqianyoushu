## 修 P0：用户上传 PDF 直接报错（`hashOriginal.toHex is not a function`）

用户实测时贴了截图：拖文件进来立刻弹这句英文，文件根本传不上。

- **根因**：`pdfjs-dist@6.2.108` 的**标准构建**在 worker 里调 `Uint8Array.prototype.toHex`（ES2026 新方法，Chrome/Edge 133+ 才有），标准构建里**没有任何 polyfill**；legacy 构建才有（`toHex: function toHex()`）。用户的浏览器内核低于 133（360 / QQ / 微信内置 / 旧 Edge 都常见）→ 计算文档指纹第一步就崩。
- **修法**：`src/utils/fileImport.js` 改引 `pdfjs-dist/legacy/build/pdf.worker.mjs?url` + `pdfjs-dist/legacy/build/pdf.mjs`。代码零改动，代价 worker 1.6MB→2.4MB。
- **验证陷阱**：`page.addInitScript` 删 `Uint8Array.prototype.toHex` **测不出来**——它只作用于页面主线程，而 toHex 在 worker 线程调用，worker 仍是 Playwright 自带新版 Chromium 的原生实现。所以改成静态断言，见下。
- **守门**：新增 `tests/unit/contract-import.test.mjs` 7 组，第 5–7 组分别断言源码引用、`node_modules` 的 legacy worker、`dist` 产物三处都不能退回标准构建；若官方将来补了 polyfill，第 6 组会打印提示。
- **顺带修两件**：
  - 新增 `ContractImportError`：底层库异常一律收敛成中文人话（按 PDF/Word/图片给不同下一步动作），原始异常只 `console.error`。之前 `toast(error.message)` 会把技术栈信息直接弹给应届生用户。
  - 扫描件 PDF 没有文字层 → 抽出的正文 <30 个汉字/字母时直接提示改用拍照 OCR，不再让空合同走进确认页。
- 一次性冒烟脚本 `scripts/verify/pdf-upload-smoke.mjs`（起服务 → 上传 qhd 真实 PDF → 等 toast）。
- 门禁：lint 零告警 / build / 11 个单测 / e2e 14 步 / verify:mvp 12/12。
- **踩到的构建坑**：`vite preview` 正在服务 `dist` 时，`vite build` 清空 `dist/assets` 会失败（safe-delete shim 报 `Some operations were aborted`）。顺序必须是：先停 preview → `rm -rf dist` → build → 再起 preview。

## V0.2 第一件：合同 docx 导出（commit ea3d64f）

用户确认「城市参数先不做，按原计划来」，于是接 V0.2 第一项：修订版 / 批注版导出。

- 新建 `app/src/features/contractDocx.js`（533 行）。**关键决定：修订版不用 Word 修订痕迹**（docx@9.7 无 `w:ins/w:del` API，硬写 XML 会出现「看着正常但房东打开看不到改动」），改为直接替换 + 红色下划线 + 文末修改清单；批注版用原生 `CommentRangeStart/End + CommentReference`（`Document({comments:{children:[ICommentOptions]}})` 只收**普通对象**，传 `new Comment()` 会报 `children is not iterable`）。
- 定位口径：`buildIndexMap` 去空白并记录原文下标 → `locateQuote` 先精确再忽略空白 → 映射回原文区间。**输出必须是原文切片**，不能输出归一化后的文本。每条风险五个 reason：applied / not-accepted / not-found / overlap / no-change，全部写进文末清单，不静默跳过。
- 界面：`WorkbenchScreen` 两个标灰菜单项开放；一条都没采纳时**拒绝导出修订版**并提示先去「修改」页采纳；`FixTab`「添加批注」与 `accept` toast 改成指向真实导出（原来写着 V0.2）。
- 测试：`tests/unit/contract-docx.test.mjs` 8 组，最后一组用 jszip 解包断言 `comments.xml` / `commentReference` / `w:u`；`mvp-flow.mjs` 从 12 步扩到 **14 步**，第 11、12 步真的点菜单、等 download 事件、读文件解包。
- 样张脚本 `app/scripts/export-sample-docx.mjs` → `app/generated-reports/contract-docx/`（该目录已被 app/.gitignore 忽略）；说明文档 `docs/tech/导出实现说明_合同docx.md`。
- 门禁：lint 零告警 / build 1.21s / 10 个单测 / e2e 14 步 / verify:mvp 12/12。
