## 对标通用合同审查工具做优缺点 gap 分析
- WebSearch 核对 2026 行业主流架构，标准六层：多格式输入 → 条款级结构化解析（clause ID/定义索引/交叉引用）→ 向量库+混合检索(vector+BM25)+rerank → 多 Agent 窄职责分解(Ingestion/Extraction/Cross-ref/Drafting) → 确定性引用校验+置信度分档+HITL 拒绝路由 → 输出+不可篡改审计日志。权威来源：futureagi.com 2026 RAG agent 指南（clause 是法律推理的最小单元，token chunk 会切断条款）、alicelabs.ai 多 agent 法律框架。
- 本项目优势 5 项：双引擎分层降级、evidence 逐字核验（命中行业引用校验点）、两阶段 Prompt+事实索引+temperature=0、输出即闭环（话术/异议是差异化，通用工具多止于标风险）、隐私默认+轻量部署+语义换算解耦。
- 缺口 5 项：无条款级检索、n-gram 检索非向量混合、单模型单轮无 agent 分解、无分层评测/金标准集（最致命）、无拒绝路径+审计链。
- **关键判断**：缺口 1/2/3/5 多是面向 C 端应届生的战略取舍，不必照抄企业级架构；真正必须补的是第 4 项「真实标准答案集」——没有它，前面所有优化都无法证明有效。此结论可直接用于 AI PM 面试谈作品集。

- 先摸清现有评测资产：`contractReviewPlaybook.js` 9 张卡 / `contractReviewPlaybookCases.js` 27 条三分类 / 桌面评测资产 45 条缺陷库（字段 case_id/item/playbook_id/variant_type/clause_text/expected_facts/expected_level/annotation_confidence/reason/basis）+ 28 份植入式合同 / `eval-defect-library.mjs` 四指标 / `real-contract-samples/` 唯一真实样本。**现有集全是自造变体+植入式，过拟合；真实合同标注数为 0。**
- **发现一个必须记住的口径坑**：缺陷库里 `expected_level:'note'` = 不该报；产品 UI 里 note = 仅提醒（会显示）。同一词两义。故规格强制拆成 `should_report`(bool) 与 `expected_level`(must/check/note) 两个独立字段，禁止用 level 推断是否应报。
- 关键设计：标注单元=独立风险语义点（非句子、非模型输出条数）；A 档进主评分/B 档只测一致性；每份必标负例测误报；卡外风险标 `playbook_id:out_of_scope` 不硬塞；evidence 必须逐字可回查（indexOf 命中）；双人独立标注 + Cohen's κ≥0.75（阈值注明是行业建议非项目实测）。
- 新脚本 `eval-real-contracts.mjs` 复用现有 `bigramJaccard`/`factCoverage`/四指标，仅换输入源与 `should_report` 判定入口；新增卡外召回、格式一致性两指标。
