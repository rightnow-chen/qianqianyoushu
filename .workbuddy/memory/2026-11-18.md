## 修复：上传任何合同都显示示例文稿结论（demo 状态串味）
- 现象：上传任意合同后结果页永远是演示数据（文件名「朝阳区_租房合同.pdf」、9 条风险、¥17,400）。
- 根因（两处叠加，均在 `App.jsx`）：
  1. `go('landing')` 只清 hash 不清内存里的 `route.demo`：landing 的 `routeToHash` 返回空 hash，但 `setRoute` 的 next 仍带 `demo:true`，内存残留。
  2. 装载 demo 的 effect 依赖 `[route.demo, session.kind]`：上传后 `session.kind:'real'` 变化触发它，命中 `route.demo && kind!=='demo'` → 把刚读出的真实 session 整份覆盖成 `DEMO_RISKS`；且 `onNext` 的 `if(!isDemo) runAnalysis()` 因此跳过，从不分析真实文件。
  该 effect 是 commit f14b4f3d（11-07 21:30）引入的。
- 修复：`go` 里 `if (screen !== 'work') next.demo = false`；effect 只依赖 `[route.demo]` 且用函数式更新避免误覆盖。
- 验证：E2E 新增第 14 步「演示后重新上传不回退到示例数据」；**反向验证**（临时回退修复）测试正好在该步失败并报「上传后不该残留演示文件名」，恢复后 21 步全过。铁证。

- 实测：链接变为 `12371.cn/...#:~:text=第七百一十条`（民法典全文页+片段，非首页）；全文页 200、正文 11.8 万字含目标条文。

## 修复：导出按钮点击没反应
- 现象：点导出菜单肉眼看不到任何东西。
- 根因：`.filebar` 有 `overflow:hidden`，导出菜单是它的绝对定位子元素（`top:34px`、高 164px），超出父容器 42px 部分被整块裁掉。E2E 用强制点击没暴露这个视觉 bug。
- 修复：`app.css` 的 `.filebar` 改 `overflow:visible`，长文件名交给 `.fn` 的 `text-overflow:ellipsis + min-width:0`。
- 实测：菜单出现在 filebar 下方、4 项 visible；21 步 E2E（含导出 docx）全过。
