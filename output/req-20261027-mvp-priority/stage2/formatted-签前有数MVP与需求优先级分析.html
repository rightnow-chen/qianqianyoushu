本报告以需求分析三步法（分辨真伪 → 确定范围 → 排定优先级）为框架，对 91 份有效问卷、用户访谈与竞品分析 v0.2 的证据进行结构化收敛，输出签前有数的 MVP 定义与 P0-P5 优先级。结论：1.0 版聚焦 P0（行业达标线：OCR 输入、风险识别、原文定位、修改建议、隐私合规）+ P1（差异化：分场景话术、待核实清单、合同内外一致性核对），P1 中"确定性分级"带准确性前置验证条件；身份核验、短租专项、商业化等列为 P4-P5 不做。

一、分析框架与数据边界

本报告采用需求分析三步法组织决策：第一步分辨需求真伪（标准：真实痛点、高频使用、愿意付出成本；方法：痛点击穿溯源、用户分层、成本-收益验证、MVP 验证法）；第二步确定需求范围（最小 MVP → 独立模块闭环 → 迭代 Roadmap）；第三步按影响面、痛度、频次排定 P0-P5 优先级，1.0 版聚焦 P0 与 P1。

数据边界说明：有效样本 91 份（原始回收 122 份，剔除 Q1 不合格 18 份、答题过快 13 份），部分子群体不足 15 人，比例推断需谨慎；访谈发现适合定性判断，不代表发生率。

数据勘误提示：A4 满意度均值原稿 3.25 存在分项人数（合计 36 人）与分母（40 人）不自洽问题，按 36 人实算约 3.06。本报告引用 AI 信任相关结论时均标注"待重算核实"，建议回原始问卷确认差额 4 人的情况后再引用。

二、Step 1：分辨需求真伪

判断标准：用户有没有真实痛点、高频使用、愿意付出成本（时间/付费）。以下用四个核心方法逐一判定：痛点击穿溯源、用户分层、成本-收益验证、MVP 验证法。

（一）真需求（证据充分，进入 MVP）

1. 签约前识别高风险条款与合同外待核实事项。痛点击穿（5-Why）：用户说"帮我审合同"→ 追问为什么 →"没时间看"（用户 C"字太小没仔细看"、用户 E"签完没看，搬家太累了"、用户 M"难的是不给你时间的那种压迫感"）→ 为什么怕 → 押金被扣、额外费用（用户 B 提前退租被扣全部押金 3000 元）→ 真实需求不是"法律分析"，而是"在签约前几分钟内判断：这份合同能不能签，有坑的话怎么改、怎么说"。痛度：58.2% 遇到合同问题，23.1% 损失 ≥2000 元，且签约前几分钟是不可再生的决策窗口。方案替代性：问亲友（经验不适用）、小红书（个案）、通用大模型（无原文定位、无固定结构、术语错误）均有明显缺陷。

2. 多格式输入 + OCR。B1 显示 70.3% 的用户手里是纸质或图片合同，OCR 不是体验增强而是入口门槛；用户 C 明确说"让我下载下来再上传到另一个平台，大概率懒得用"——输入摩擦必须压到最低。

3. 修改建议 + 分场景沟通话术。用户 D："我要的不仅是标出风险，还要告诉我这个风险怎么改、改完发给房东怎么说"；用户 B："最需要的不是法律分析，而是普通人能看懂的风险标注 + 怎么用"。B2 显示 34.1% 愿意修改对方合同，行动意愿真实存在。竞品分析确认：国内竞品与通用大模型公开资料中均未见签约前分场景话术；谈判信见于海外产品（TheLeaseCheck / LeaseSnipe / LeaseChat），无中文分场景版本。真需求 + 差异化空白，双重成立。

4. 待核实清单（合同主体 / 出租人身份 / 转租授权 / 口头承诺 / 合同外费用）。访谈证据：用户 A"中介口头说物业费房东交，但合同里没写"；用户 E"我怎么知道跟我签合同的人是不是有权出租的人"；用户 L"管理费、水电费涨价都是口头通知"。证据等级说明：问卷未测发生率，属定性访谈发现；但竞品同样空白，且只要命中一次即是重大损失场景。进入 MVP，上线后用埋点验证使用率。

5. 隐私脱敏 + 不存储 + 责任边界声明（合规类必做）。用户 M："合同里有我的姓名、身份证号、住址，上传到一个不明平台我会担心隐私。"按 AI 产品避坑原则：合规类需求必须处理，不以商业回报衡量；同时 LeaseSnipe 案例证明"免注册 + 不存储"是建立信任的最短路径——合规与增长在此重合。

（二）存疑需求（用 MVP 验证法处理）

确定性分级 + 转律师提示：A4 显示 44% 用过 AI，满意度均值待重算（约 3.06）——用户有使用基础但信任未充分建立。方向正确（多数竞品声明"非法律意见"但边界模糊），但前提是分级本身要准：标"确定"的条款若被专业人士推翻，信任崩塌比通用免责更糟。处理：保留在 P1，带前置条件——先用评测集验证"确定"标注的准确率，达标后再上线（V1.1）。

（三）伪需求与暂不做（逐条给出判定方法）

需求判定方法结论
出租人身份真伪核验成本-收益验证用户 E 称"刚需中的刚需"，痛点为真，但技术成本（政务/征信数据源）与合规成本远超当前可交付价值；降级为"待核实提醒"（提示核对，不判断真伪），V2.0 评估合作方案
短租/二房东/转租/隔断房专项用户分层非核心目标用户（应届生首次租房主流程）的高频需求，属低频特殊场景；留作后续专项验证方向

三、Step 2：确定需求范围

核心思路：先做最小 MVP，再做模块闭环，最后迭代升级，拒绝贪多求全。

（一）最小 MVP 闭环（一条核心旅程）

合同输入（拍照/图片/PDF/Word/粘贴，含 OCR）→ 风险摘要（按严重度排序，押金/提前退租/维修/水电附加费优先）→ 单条风险详情（原文定位 + 可能后果 + 修改建议 + 分场景话术）→ 待核实清单 → 修改后复查。用户全程只需要完成一件事：上传合同 → 在签约前拿到"能不能签、怎么改、怎么说、还要问什么"的结论。

（二）独立模块闭环（每个功能有始有终，不断"断头路"）

模块闭环路径验收标准
输入模块拍照/上传/粘贴 → OCR → 文本确认覆盖 70.3% 纸质/图片场景；OCR 失败可手动粘贴兜底；上传前提示脱敏
风险摘要模块识别 → 严重度排序 → 定位原文押金/退租/维修/附加费优先呈现；正常条款不标风险（埋雷合同 M8 专项测试误报）
行动模块风险 → 修改建议 → 话术（礼貌版/协商版）话术可直接复制发给房东/中介，无需二次加工
待核实模块生成清单 → 逐项勾选 → 提示补写入合同覆盖主体/身份/授权/口头承诺/合同外费用五类
复查模块修改后重新评估 → 前后对比确认修改是否消除风险，形成闭环

（三）主流 / 边缘 / 异常需求分层

拆解维度需求内容
主流流程需求（核心）OCR 多格式输入；重点条款识别（押金/提前退租/维修/水电附加费）；风险按严重度排序；原文定位；后果解释；修改建议；分场景话术；待核实清单；修改后复查
边缘流程需求（辅助）审查结果导出为文本/图片（便于发给亲友参谋）；首笔支出/入住成本汇总（可选）；预算登记（可选）
异常流程需求（兜底）OCR 识别失败 → 提示手动粘贴文本；AI 不确定 → 明确标注"存疑"并建议咨询专业人士；正常条款误报 → 提供反馈入口；全局常驻隐私说明（脱敏上传 + 不存储）与非法律意见声明

（四）产品迭代 Roadmap

版本范围
V1.0（MVP）核心闭环上线：输入 + 风险摘要 + 修改建议 + 话术 + 待核实清单 + 复查；隐私脱敏与免责声明作为默认能力内置
V1.1确定性分级 + 转律师提示（前置：评测集验证"确定"标注准确率达标）；话术库按真实反馈扩充；接入政府示范文本作对照规则库；误报优化
V2.0多合同管理、费用/成本汇总、城市级租客权利库（维修时限/押金退还等地方规则）；据数据决策是否推进身份核验合作与特殊场景（短租/二房东）专项

四、Step 3：需求优先级（P0-P5）

按影响面、痛度（方案替代性）、频次三个维度评级。频次说明：租房签约属低频场景（约 1-2 年一次），但痛度极高（23.1% 损失 ≥2000 元）、时机不可错过（签约前几分钟是唯一窗口）、且现有方案替代性弱——按"痛度与替代性越强优先级越高"，P0 判定以痛度为主要依据。

等级需求判定依据
P0多格式输入 + OCRB1 70.3%；入口门槛，无此功能 7 成用户无法使用
P0重点条款识别 + 严重度排序A1 58.2%；访谈风险类型高度集中（押金/退租/维修/附加费）
P0原文定位 + 后果解释信任基础；用户 B"普通人能看懂"；竞品达标线
P0修改建议（改写条款）用户 D 直接表达；B2 34.1% 愿改合同
P0隐私脱敏 + 不存储 + 责任边界声明用户 M 明确担忧；AI 产品合规类必做
P1分场景话术（礼貌版/协商版）竞品空白 + 用户证据双重成立；差异化核心
P1待核实清单竞品空白 + 访谈证据；填补最大空白
P1合同内外一致性核对（口头 vs 书面）竞品空白 + 用户 A/L 证据；微创新候选首位
P1修改后复查MVP 闭环收尾必需；得理已有，属达标线
P1（带前置条件）确定性分级 + 转律师提示价值属 P1，但须先过准确性验证，未达标则顺延 V1.1
P2-P3审查结果导出、费用汇总、预算登记、多合同对比、城市规则库锦上添花，验证核心闭环后再做
P4-P5身份真伪核验、短租/二房东专项、预算房源匹配、验房退租、线上签约内嵌、商业化伪/暂缓需求：成本高、无证据或未验证

1.0 版聚焦 P0 + P1：P0 保证"能用"（行业达标线），P1 保证"不同"（竞品空白即差异化）。

五、收尾结论

一句话结论：签前有数为刚毕业、第一次租房的年轻人解决"签约前看不懂合同、不知道坑在哪、不知道怎么改和怎么说"的痛点，做【合同 OCR 输入 + 风险摘要 + 原文定位 + 修改建议 + 分场景话术 + 待核实清单 + 修改后复查】的 P0-P1 核心功能，不做【身份真伪核验、短租/二房东专项、验房退租、房源匹配、商业化】等无证据或成本收益不成立的功能，靠【签约前中文分场景话术 + 合同内外一致性核对 + 合同外待核实清单】这三个公开资料未见成熟做法且自有用户证据的差异化能力，区别于通用大模型与通用合同审查工具。

（一）差异化切入点对照

切入点应用
垂直场景深耕只做租房单场景（对比得理/通义法睿的全品类法律审查），表达与规则全部为租房定制
用户分层设计面向应届生首次租房：大白话 + 行动导向，不使用律师向功能（得理个人版教训）
体验终局把竞品止步的"标风险"推进为"风险 → 修改 → 话术 → 待核实 → 复查"完整闭环

六、下一步验证事项

  1. 用埋雷合同 M1-M8 横测竞品与本产品，验证 3 项差异化是否真实成立；
  2. 脱敏真实合同可用性测试，观察话术复制率与待核实清单勾选率；
  3. 回原始问卷重算 A4 满意度均值（分项人数 36 vs 分母 40 不自洽）；
  4. 上线后跟踪留存与采纳率，验证低频场景下的"用完即走"是否成立。
