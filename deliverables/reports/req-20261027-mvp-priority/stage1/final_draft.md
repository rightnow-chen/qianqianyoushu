# 签前有数 MVP 与需求优先级分析报告

**分析方法**：需求分析三步法（分辨真伪 → 确定范围 → 排定优先级）

**证据输入**：《租房合同审查产品需求验证分析报告》（91 份有效问卷 + 用户访谈）、《签前有数》竞品分析报告 v0.2（联网调研，2026-10-27）

**数据边界说明**：有效样本 91 份，部分子群体不足 15 人；A4 满意度均值原稿 3.25 存在分项人数（合计 36）与分母（40）不自洽问题，按 36 人实算约 3.06，本报告引用 AI 信任相关结论时均标注"待重算核实"。访谈发现适合定性判断，不代表发生率。

## 一、Step 1：分辨需求真伪

判断标准：用户有没有真实痛点、高频使用、愿意付出成本（时间/付费）。用四个核心方法逐一判定：痛点击穿溯源、用户分层、成本-收益验证、MVP 验证法。

### 1.1 真需求（证据充分，进入 MVP）

**1. 签约前识别高风险条款与合同外待核实事项**

- 痛点击穿（5-Why）：用户说"帮我审合同"→ 追问为什么 →"没时间看"（用户 C"字太小没仔细看"、用户 E"签完没看，搬家太累了"、用户 M"难的是不给你时间的那种压迫感"）→ 为什么怕 → 押金被扣、额外费用（用户 B 提前退租被扣全部押金 3000 元）→ **真实需求不是"法律分析"，而是"在签约前几分钟内判断：这份合同能不能签，有坑的话怎么改、怎么说"**。
- 痛度极高：58.2% 遇到合同问题，23.1% 损失 ≥2000 元；且签约前几分钟是不可再生的决策窗口，错过即失效。
- 愿意付出成本：70.3% 的合同是纸质或图片形态但用户仍愿意拍照输入（B1）；34.1% 愿意修改对方合同（B2）——行动意愿真实存在。
- 方案替代性：问亲友（经验不适用）、小红书（个案）、通用大模型（无原文定位、无固定结构、术语错误）均有明显缺陷，替代性弱。

**2. 多格式输入 + OCR**

- B1 显示 70.3% 的用户手里是纸质或图片合同，OCR 不是体验增强而是入口门槛；访谈中用户 C 明确说"让我下载下来再上传到另一个平台，大概率懒得用"——输入摩擦必须压到最低。

**3. 修改建议 + 分场景沟通话术**

- 用户 D："我要的不仅是标出风险，还要告诉我这个风险怎么改、改完发给房东怎么说"；用户 B："最需要的不是法律分析，而是普通人能看懂的风险标注 + 怎么用"。
- 竞品分析确认：国内竞品与通用大模型公开资料中均未见签约前分场景话术；谈判信见于海外产品（TheLeaseCheck/LeaseSnipe/LeaseChat），无中文分场景版本。**真需求 + 差异化空白，双重成立。**

**4. 待核实清单（合同主体/出租人身份/转租授权/口头承诺/合同外费用）**

- 访谈证据：用户 A"中介口头说物业费房东交，但合同里没写"；用户 E"我怎么知道跟我签合同的人是不是有权出租的人"；用户 L"管理费、水电费涨价都是口头通知"。
- 证据等级说明：问卷未测发生率，属定性访谈发现；但竞品同样空白，且产品价值不依赖其发生率——只要命中一次即是重大损失场景。进入 MVP，上线后用埋点验证使用率。

**5. 隐私脱敏 + 不存储 + 责任边界声明（合规类必做）**

- 用户 M："合同里有我的姓名、身份证号、住址，上传到一个不明平台我会担心隐私。"
- 按方法论"AI 产品避坑"：合规类需求是必须处理的，不以商业回报衡量。同时 LeaseSnipe 案例证明"免注册 + 不存储"是建立信任的最短路径，比堆免责声明更有效——合规与增长在此重合。

### 1.2 存疑需求（用 MVP 验证法处理，不直接判真）

**确定性分级 + 转律师提示**：A4 显示 44% 用过 AI，满意度均值待重算（约 3.06）——用户有使用基础但信任未充分建立。方向正确（竞品分析：多数产品声明"非法律意见"但边界模糊），但前提是分级本身要准：标"确定"的条款若被专业人士推翻，信任崩塌比通用免责更糟。**处理：保留在 P1，带前置条件——先用评测集验证"确定"标注的准确率，达标后再上线（V1.1）。**

### 1.3 伪需求 / 暂不做（逐条给出判定方法）

| 需求 | 判定方法 | 结论 |
|------|---------|------|
| 出租人身份真伪核验 | 成本-收益验证 | 用户 E 称"刚需中的刚需"，痛点为真，但技术成本（政务/征信数据源对接）与合规成本远超当前可交付价值；降级为"待核实提醒"（提示用户核对，不判断真伪）。等 V2.0 评估合作方案 |
| 短租/二房东/转租/隔断房专项 | 用户分层 | 非核心目标用户（应届生首次租房主流程）的高频需求，属低频特殊场景；用户 N/L 的反馈留作后续专项验证方向 |
| 预算/房源匹配/地图通勤/验房/退租证据包 | 证据检查 | 本轮需求验证未覆盖，无任何用户证据；不符合"签约前几分钟"核心场景 |
| 线上签约流程内嵌 | 成本-收益验证 | 访谈支持（入口靠近签约动作），但需平台合作，当前资源不可达；暂缓 |
| 商业化/付费墙 | MVP 验证法 | 付费意愿未验证；竞品价格调研（$9/份、4 元/页）显示单次审查撑不起商业化；MVP 阶段不设计收费点 |
| 0-100 评分体系照搬 TheLeaseCheck | 成本-收益验证 | 需建中国租房本地规则库支撑评分，成本高且准确性未经横测；用三级严重度（高/中/低）替代 |
| 风险规则按问卷频次排序 | 证据复核 | B4 三项（维修 25/退租 24/损坏 20）差距在 n=91 下无区分意义，且频次不等于严重度；降为规则优先级参考方法，与损失金额综合排序，不作为产品功能 |

## 二、Step 2：确定需求范围

核心思路：先做最小 MVP，再做模块闭环，最后迭代升级，拒绝贪多求全。

### 2.1 最小 MVP 闭环（一条核心旅程）

合同输入（拍照/图片/PDF/Word/粘贴，含 OCR）→ 风险摘要（按严重度排序，押金/提前退租/维修/水电附加费优先）→ 单条风险详情（原文定位 + 可能后果 + 修改建议 + 分场景话术）→ 待核实清单 → 修改后复查。

用户全程只需要完成一件事：上传合同 → 在签约前拿到"能不能签、怎么改、怎么说、还要问什么"的结论。

### 2.2 独立模块闭环（每个功能有始有终，不断"断头路"）

| 模块 | 闭环路径 | 验收标准 |
|------|---------|---------|
| 输入模块 | 拍照/上传/粘贴 → OCR → 文本确认 | 覆盖 70.3% 纸质/图片场景；OCR 失败可手动粘贴兜底；上传前提示脱敏 |
| 风险摘要模块 | 识别 → 严重度排序 → 定位原文 | 押金/退租/维修/附加费优先呈现；正常条款不标风险（埋雷合同 M8 专项测试误报） |
| 行动模块 | 风险 → 修改建议 → 话术（礼貌版/协商版） | 话术可直接复制发给房东/中介，无需二次加工 |
| 待核实模块 | 生成清单 → 逐项勾选 → 提示补写入合同 | 覆盖主体/身份/授权/口头承诺/合同外费用五类 |
| 复查模块 | 修改后重新评估 → 前后对比 | 确认修改是否消除风险，形成闭环 |

### 2.3 主流 / 边缘 / 异常需求分层

| 拆解维度 | 需求内容 |
|---------|---------|
| 主流流程需求（核心） | OCR 多格式输入；重点条款识别（押金/提前退租/维修/水电附加费）；风险按严重度排序；原文定位；后果解释；修改建议；分场景话术；待核实清单；修改后复查 |
| 边缘流程需求（辅助） | 审查结果导出为文本/图片（便于发给亲友参谋）；首笔支出/入住成本汇总（可选项）；预算登记（可选项） |
| 异常流程需求（兜底） | OCR 识别失败 → 提示手动粘贴文本；AI 不确定 → 明确标注"存疑"并建议咨询专业人士；正常条款误报 → 提供反馈入口；全局常驻隐私说明（脱敏上传 + 不存储）与非法律意见声明 |

### 2.4 产品迭代 Roadmap

| 版本 | 范围 |
|------|------|
| V1.0（MVP） | 核心闭环上线：输入 + 风险摘要 + 修改建议 + 话术 + 待核实清单 + 复查；隐私脱敏与免责声明作为默认能力内置 |
| V1.1 | 确定性分级 + 转律师提示（前置：评测集验证"确定"标注准确率达标）；话术库按真实反馈扩充；接入政府示范文本作对照规则库；误报优化 |
| V2.0 | 多合同管理、费用/成本汇总、城市级租客权利库（维修时限/押金退还等地方规则）；据数据决策是否推进身份核验合作与特殊场景（短租/二房东）专项 |

## 三、Step 3：需求优先级（P0-P5）

按影响面、痛度（方案替代性）、频次三个维度评级。**频次说明**：租房签约属低频场景（约 1-2 年一次），但痛度极高（23.1% 损失 ≥2000 元）、时机不可错过（签约前几分钟是唯一窗口）、且现有方案替代性弱——按方法论"痛度与替代性越强优先级越高"，P0 判定以痛度为主要依据。

| 等级 | 需求 | 判定依据 |
|------|------|---------|
| P0 | 多格式输入 + OCR | B1 70.3%；入口门槛，无此功能 7 成用户无法使用 |
| P0 | 重点条款识别 + 严重度排序 | A1 58.2%；访谈风险类型高度集中（押金/退租/维修/附加费） |
| P0 | 原文定位 + 后果解释 | 信任基础；用户 B"普通人能看懂"；竞品达标线 |
| P0 | 修改建议（改写条款） | 用户 D 直接表达；B2 34.1% 愿改合同 |
| P0 | 隐私脱敏 + 不存储 + 责任边界声明 | 用户 M 明确担忧；AI 产品合规类必做 |
| P1 | 分场景话术（礼貌版/协商版） | 竞品空白 + 用户证据双重成立；差异化核心 |
| P1 | 待核实清单 | 竞品空白 + 访谈证据；填补最大空白 |
| P1 | 合同内外一致性核对（口头 vs 书面） | 竞品空白 + 用户 A/L 证据；微创新候选首位 |
| P1 | 修改后复查 | MVP 闭环收尾必需；得理已有，属达标线 |
| P1（带前置条件） | 确定性分级 + 转律师提示 | 价值属 P1，但须先过准确性验证，未达标则顺延 V1.1 |
| P2-P3 | 审查结果导出、费用汇总、预算登记、多合同对比、城市规则库 | 锦上添花，验证核心闭环后再做 |
| P4-P5 | 身份真伪核验、短租/二房东专项、预算房源匹配、验房退租、线上签约内嵌、商业化 | 伪/暂缓需求：成本高、无证据或未验证 |

**1.0 版聚焦 P0 + P1**：P0 保证"能用"（行业达标线），P1 保证"不同"（竞品空白即差异化）。

## 四、收尾结论

**一句话**：签前有数为刚毕业、第一次租房的年轻人解决"签约前看不懂合同、不知道坑在哪、不知道怎么改和怎么说"的痛点，做【合同 OCR 输入 + 风险摘要 + 原文定位 + 修改建议 + 分场景话术 + 待核实清单 + 修改后复查】的 P0-P1 核心功能，不做【身份真伪核验、短租/二房东专项、验房退租、房源匹配、商业化】等无证据或成本收益不成立的功能，靠【签约前中文分场景话术 + 合同内外一致性核对 + 合同外待核实清单】这三个公开资料未见成熟做法且自有用户证据的差异化能力，区别于通用大模型与通用合同审查工具。

**差异化切入点对照**（方法论：产品突围关键）：

| 切入点 | 应用 |
|--------|------|
| 垂直场景深耕 | 只做租房单场景（对比得理/通义法睿的全品类法律审查），表达与规则全部为租房定制 |
| 用户分层设计 | 面向应届生首次租房：大白话 + 行动导向，不使用律师向功能（得理个人版教训） |
| 体验终局 | 把竞品止步的"标风险"推进为"风险 → 修改 → 话术 → 待核实 → 复查"完整闭环 |

**下一步验证事项**（MVP 验证法落地）：① 用埋雷合同 M1-M8 横测竞品与本产品，验证 3 项差异化是否真实成立；② 脱敏真实合同可用性测试，观察话术复制率与待核实清单勾选率；③ 回原始问卷重算 A4 满意度均值（分项人数 36 vs 分母 40 不自洽）；④ 上线后跟踪留存与采纳率，验证低频场景下的"用完即走"是否成立。
