# 隐蔽风险进阶包 测试说明与标准答案

本包专门测试需要跨条款、跨附件、跨格式阅读才能发现的风险。人物、地址和金额均为虚构；这些材料只用于产品测试，不是签署建议。答案中的“风险”表示应提示用户核对或协商，不等于该条款当然无效。

## 文件安排

| 文件 | 用途 |
| --- | --- |
| 01_隐蔽组合型_正文.md | 长正文、定义与条件组合、通知程序、续租和结算链条 |
| 02_隐蔽组合型_同文PDF.pdf | 与 MD 同文，用于检测跨格式一致性和证据定位 |
| 03_表格与补充协议_复杂Word.docx | 表格、正文、补充协议之间的优先级和金额冲突 |

| 05_低风险近似对照.txt | 负例，用来观察误报 |
| 06_OCR对照原文.txt | 图片 OCR 的逐字基准，不要上传给审查功能 |

## 必须命中的隐蔽风险

| 编号 | 证据定位 | 期待识别 |
| --- | --- | --- |
| A1 | 第三条“月度应付款”与“租金逾期” | 代收项目被纳入“租金逾期”，可能导致小额水电争议触发租金逾期后果；应提示区分基础租金和代收费用 |
| A2 | 第四条“基础租金不调整”与“代收项目可按实际变化调整” | 不要只报“租金不涨”；应提示总月度支出仍可能上涨，需说明调整依据、通知和核对方式 |
| A3 | 第四条不续租通知 | 同时要求邮件和小程序，且未同时提交即进入六个月滚动续租；应提示通知方式和自动续租后果 |
| A4 | 滚动续租报价 | “甲方届时对外公布的同类房屋报价”缺少可验证基准，可能形成单方定价；应建议增加计算口径和确认机制 |
| A5 | 第五条押金结算 | 结算完成才开始计算10个工作日；账单未出可暂留平均金额，返还时间可能不确定；应提示暂留上限、账单期限和明细 |
| A6 | 第六条维修 | 每次报修前500元由乙方承担，且报销要求、紧急例外和“甲方确认”组合起来，可能把自然故障成本转给租客；应分清责任原因和报销条件 |
| A7 | 第七条入户 | 12小时通知 + 4小时未回复视为同意 + 合理时段，形成默认同意机制；应提示通知是否实际送达和替代时间机制 |
| A8 | 第七条数据 | 门禁、智能锁和小程序记录可提供给多类第三方；应提示数据范围、用途、保存期限和必要性 |
| A9 | 第八条访客 | 7晚/30日14晚的累计阈值会把普通访客变成“居住成员变更”，并可能触发公共服务费重算；应提示计算方式和费用依据 |
| A10 | 第九条提前退租 | 乙方固定一个月补偿并可能补足实际损失，甲方只按具体事由和实际损失处理，责任结构不完全对称；应提示双方责任标准和损失证明 |
| A11 | 第九条逾期 | “租金逾期”沿用第三条定义，代收费用争议可能触发押金抵扣和补足押金义务；应做跨条款关联 |
| A12 | 第十条恢复 | 使用“同类材料合理市场价格”但未约定报价来源和复核机制；应提示报价、折旧和自然损耗证据 |
| A13 | 第十一条通知 | 甲方任一渠道即视为发送，乙方重要通知必须双渠道并保留成功记录，存在程序不对称；应提示生效与送达规则 |
| A14 | 第十一条文件效力 | 只有明确写明“替代原约定”的双方确认文件才改变正文，自动账单不改变合同；应提示用户不要把账单默认当成合同变更 |
| A15 | 03 Word 的表格、正文、补充协议 | 表格的返还期限、补充协议的账单异议和正文的暂留规则需要合并阅读；应发现“最后一次明确替代”规则，而不能擅自挑一处作为唯一答案 |
| A16 | 04 图片 OCR | 应准确识别4,280元、180元、8,560元、10个工作日、12小时、4小时、5日和六个月；任何数字错位都属于导入缺陷 |

## 可提示但必须保留不确定性

- “访客超过7晚”是否构成居住成员变更，取决于物业规则、实际居住情况和费用标准；不能直接断言违法。
- 每次报修前500元的安排是否合理，取决于故障原因、合同全文和实际维修项目；应提示协商，不要自动判定有效或无效。
- 甲方提前解除按具体事由处理，可能需要结合出售、自住、维修事实和损失证据；重点测试系统是否会把不对称写法解释清楚。
- 代收服务费上调是否可行，取决于物业收费依据、通知和双方约定；系统应提示核对账单与依据。

## 不能误报的负例

05 文件中的“租期内基础租金不变”“账单应提供核对”“7个工作日返还”“提前24小时通知并协商”“正常损耗不扣”，不应被误报成单方涨租、任意扣押金或随意入户。不要因为合同缺少某一项细节，就把“未约定”当成“明文允许”。

## 建议评分

| 维度 | 分值 | 通过建议 |
| --- | ---: | --- |
| 跨条款召回 | 30 | A1-A15 至少命中13项，并能指出涉及的两处以上条款 |
| 数字和 OCR | 15 | A16 的金额、日期、期限、比例全部正确 |
| 证据逐字绑定 | 20 | 每个结论都能回到当前文件；MD 与 PDF 实质结果一致 |
| 误报控制 | 15 | 05 不产生明显高风险；“风险提示”和“确定违法”有区别 |
| 冲突与优先级 | 10 | 03 能发现表格、正文、补充协议的关系，不擅自替双方决定适用版本 |
| 建议质量 | 10 | 建议补充上限、期限、通知、凭证、复核机制，而不是只说“删除条款” |

建议通过线：总分至少85；A3、A5、A7、A11、A15必须命中；不得出现当前合同不存在的金额、日期或证据。出现“无证据引用”或把风险直接断言为确定违法，按阻断级 badcase 处理。

## Badcase 记录重点

遇到漏报时，记录它是单条漏读还是跨条款关联失败；遇到误报时，记录系统把“未约定”“允许”“可能发生”中的哪一种误读成了确定事实；遇到 OCR 错误时，单独记录原图、OCR 文本和风险输出，不要只记录最终结论。
