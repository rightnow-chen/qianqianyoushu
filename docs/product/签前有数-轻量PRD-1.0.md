# 签前有数 · 1.0 轻量 PRD

> 一句话：面向第一次租房的毕业生，把「这份合同哪里有坑」讲清楚，把「怎么跟房东谈」准备好。
> 交付形态：免登录 Web 单页应用（React + Vite），小程序不在本版范围。
> 本版基准日期：2026-10-08。本文档定义 1.0 产品范围，用于对齐后续开发与演示。

---

## 〇、本版相对上一版 PRD 的变化（先读这个）

上一版 PRD 定义的是「签约决策助手」：填需求 → 填房源 → 传合同 → 出三级签约判断。实际迭代后，产品主线收敛为「合同审查 → 谈判 → 复查」，原「签约决策」方向的输入表单、费用测算与三级判断**整体砍掉**。具体变化如下：

**砍掉**

| 砍掉项 | 原因 |
|---|---|
| 「我的租房需求」「房源与合同」输入页（房源与预算） | 主线收敛为合同驱动：用户拿到合同就能开始，填表是使用门槛，首版不设 |
| 签约判断独立页与三级结论（建议暂缓 / 待确认 / 可继续） | 依赖需求/房源表单的预算与底线输入，随表单一并砍掉；风险程度由审查结果的评分与高风险数承载 |
| 费用测算（月度支出 / 首次付款 / 预算冲突提示） | 输入来源（房源费用表单）被砍，失去数据入口，随表单一并砍掉 |
| 信息可信度三级标注（合同约定 > 口头承诺 > 用户猜测） | 随房源表单砍掉；可信度由「原文证据绑定 + 法条溯源」承载 |
| 首次付款预算 upfrontBudget、其他签约付款 otherUpfrontFees | 属房源表单字段，随表单砍掉 |
| 沟通记录输入 communicationText | 谈判台上线后，逐条对话记录比整段粘贴更好用 |
| 地图通勤计算 | 维持暂不纳入，用户自填通勤分钟数 |

**新增（超出上一版 PRD）**

| 新增 | 说明 |
|---|---|
| 谈判台（独立模块） | 待谈清单 + AI 军师逐条对话 + 条款三态跟踪（待谈/谈中/已谈妥），谈妥内容一键写回合同 |
| 法条溯源 | 每条风险附具体法条依据（住房租赁条例、民法典等），可点开原文链接核对 |
| 修订合同生成 | 采纳/谈妥的修改自动汇成修订版合同草案 + 修改对比，导出 DOCX |
| 文件导入 | TXT / MD / DOCX / PDF / 合同图片 OCR（低置信度提示人工复核） |
| 仅本地分析模式 | 一键开关，合同与对话不出设备；本地数据可一键导出/清除 |

## 一、产品概览

| 维度 | 内容 |
|---|---|
| 产品名称 | 签前有数（副标：租房合同审查助手） |
| 目标用户 | 即将毕业或毕业一年内、第一次独立租房、预算有限、缺少合同阅读和谈判经验的年轻人 |
| 核心场景 | 已看中一套候选房源，拿到（或即将拿到）合同，签之前想知道：哪些条款要谈、怎么谈、谈完怎么确认改好了 |
| 核心痛点 | 看不懂合同；知道有坑不知道怎么谈；谈完口头答应，白纸黑字没改等于白谈 |
| MVP 目标 | 新用户在 10 分钟内走完「导入合同 → 看懂风险 → 准备话术 → 谈妥改稿 → 复查确认」一条链路 |
| 第一版边界 | 不做：房源真实性鉴定、交易支付、复杂纠纷法律意见、自动抓取房源、地图路线、房东信用评分、小程序 |

## 二、核心流程

主线闭环（三步，对应首页叙事和步骤条）：

```
① 审合同 ──────→ ② 谈判台 ──────→ ③ 复查导出
粘贴/导入合同      逐条准备话术       修订文本写回编辑区
逐条标出风险      记录房东回应       重新审查验证风险消除
绑定原文+法条     标记谈妥→写回合同   导出报告/修订合同 DOCX
```

①②③ 全程围绕同一份合同展开：审查发现的问题进谈判台逐项处理，谈判结果写回合同后复查验证。1.0 不设独立的需求/房源填写环节。

分步说明：

| 步骤 | 用户动作 | 系统行为 | 边界处理 |
|---|---|---|---|
| 1 进入 | 打开首页，点「开始审查合同」或载入演示案例 | 展示产品定位与两条演示路线（90 秒 / 5 分钟） | 演示数据始终标注「演示案例」 |
| 2 导入 | 粘贴合同正文，或导入 TXT/MD/DOCX/PDF/图片 | 解析文本入库；OCR 显示置信度 | OCR 低置信度时提示人工核对；导入失败给出原因 |
| 3 审查 | 点「开始审查」 | 本地规则库逐条匹配（即时返回），AI 补充分析；输出风险评分 + 逐条风险 | 分析中禁重复提交、可取消；AI 失败时本地规则结果照常展示并明示 |
| 4 看结果 | 逐条查看风险 | 每条含：等级、原文引用、大白话解释、替代条款、谈判话术、法条依据；点击引用可回查原文高亮 | 无证据的 AI 结论直接丢弃，不展示 |
| 5 采纳 | 逐条或全部采纳修改建议 | 生成修订合同草案与修改对比；已采纳卡片移出待处理 | 仅勾选不等于已修改，需写回合同 |
| 6 谈判 | 进谈判台，逐条选问题 | AI 军师生成/现场调整话术（语气可选）；记录房东回应，标记「待谈/谈中/已谈妥」 | 「已谈妥」只是协商结果，须写回合同才生效 |
| 7 复查 | 写回修改，回到审合同页重新审查 | 验证旧风险是否消除，剩余问题继续跟进 | 「已沟通」不直接视为风险已解决 |
| 8 导出 | 下载 DOCX | 审查报告 / 修订合同导出，留档或发给房东 | 导出内容与页面所见一致 |

## 三、页面结构

| 页面（模块） | 主要内容 | 核心操作 | 完成条件 |
|---|---|---|---|
| 使用总览（首页） | 产品定位、数字锚点（55 类风险点 / 结论可溯源 / 10 分钟）、三步流程、法条溯源示例、两个典型场景、演示路线 | 开始审查合同、看真实案例、进入各模块 | 能进入审查或载入演示案例 |
| 审合同（主模块） | 合同输入区（粘贴/导入/演示）、风险清单、风险评分卡、证据高亮、采纳操作、修订草案预览 | 粘贴或导入合同、开始审查、点击证据回查原文、逐条/全部采纳、导出报告 | 至少完成一次审查并看到逐条结果 |
| 谈判台（主模块） | 左：待谈清单（按状态与风险排序）；中：AI 军师对话（现场生成话术）；右：条款档案（原文证据、法条、底线、三态记录） | 选择条款、生成/复制话术、记录回应、切换三态、把「已谈妥」写回合同 | 至少一条条款完成「谈妥 → 写回」 |
| AI 助手（工具） | 对话面板，结合当前模块、合同风险、谈判进度作答 | 提问、追问、复制回复 | 拿到可执行的回答；模型不可用时本地兜底可答 |

全局框架：左侧边栏（品牌入口 → 首页；导航：审合同 / 谈判台 / AI 助手；合同状态提示；仅本地分析开关；导出/清除全部数据），顶栏随模块切换上下文，URL `?module=` 支持深链直达。

## 五、交互要点

1. **结论先行**：审查结果先给风险评分与高风险数，再展开逐条风险；每条风险先标题后细节。
2. **证据可回查**：点击任一风险的原文引用，定位并高亮合同原文；这是产品信任的根基，不允许任何「无出处风险」。
3. **状态贯穿**：条款三态（待谈/谈中/已谈妥）在审合同与谈判台之间共享同一份数据，切换模块不丢状态。
4. **防呆**：分析中禁重复提交、可取消；迟到响应不得覆盖当前页面结果。
5. **失败兜底可见**：AI 不可用时明示「已切换本地规则/知识库」，功能不中断、不假装成功。
6. **演示诚实**：演示案例永远带「演示案例」标识；目标类数字（如「10 分钟」）标注为待验证目标而非成绩。
7. **无障碍与适配**：颜色不作为风险唯一区分方式（等级同时用文字表达）；正文对比度满足 WCAG AA；手机宽度不横向溢出；动效尊重 reduced motion。
8. **深链直达**：`?module=contract|negotiation|ai` 可直达模块，浏览器前进后退可用。

## 六、非功能要求

| 类别 | 要求 |
|---|---|
| 性能 | 本地规则审查即时返回（<1s）；首屏可交互 <2s（本地部署） |
| 隐私安全 | 合同与对话默认不出设备；开启远端时仅发送本次任务所需内容，服务端日志不落合同/沟通全文；API 密钥只存服务端环境变量 |
| 可靠性 | 模型超时/异常自动降级本地规则与知识库；OCR 低置信度强制人工复核提示 |

| 兼容 | 现代浏览器（Chrome/Edge/Safari 最新两个大版本）；移动端优先保证核心流程可用 |
| 数据 | localStorage 带 schemaVersion 与 updatedAt；合同正文与分析结果默认仅存页面内存，刷新前提示 |
| 质量 | `npm run lint` + `npm run build` 为提交门槛；AI 规则与 RAG 样本有回归测试 |

## 八、Vibe Coding 实现思路

### 8.1 技术形态

- 前端：React + Vite 单页应用，`npm run dev` 即可完整演示（本地规则全在前端跑）。
- 后端：一个轻量 Node 代理（`/api`），只负责三件事——模型调用、RAG 检索、OCR；密钥全部在服务端环境变量。
- 部署：静态托管 + 一个 Serverless 函数即可，无数据库、无登录。

### 8.2 代码分层（给 AI 编码工具的模块边界）

```
src/
  features/     纯函数层：风险规则库、证据校验、话术生成 —— 不碰 DOM、可单测
  utils/        工具层：文件导入、剪贴板、DOCX 导出
  components/   展示层：一个模块一个组件（首页 / 审合同 / 谈判台 / AI 助手）
  constants/    配置：存储键、服务商预设、字段选项
  data/         数据：演示合同、知识库、法条映射
server/         AI 代理（模型转发 + RAG + OCR），无状态
```

### 8.3 三条铁律（防 AI 编码翻车）

1. **确定性校验绝不交给模型**：证据逐字匹配、风险评分与分级，全部纯代码实现；AI 输出只做「文本理解」和「话术生成」，且必须通过证据校验才能上屏。
2. **规则库数据化**：每条风险规则是一个对象（id / 触发条件 / 等级 / 大白话 / 替代条款 / 话术 / 法条），新增风险 = 加一条数据，不改逻辑。
3. **每步可验证**：每次改动独立可 build、可演示；规则库、审查页、采纳修订、谈判台、AI 兜底、导入导出按此顺序逐个交付，不一次堆一大坨。

### 8.4 建议开发顺序

① 本地规则库 + 证据绑定 → ② 审合同主页面 → ③ 采纳 + 修订 + 复查 → ④ 谈判台 → ⑤ AI 助手 + 本地兜底 → ⑥ 导入/导出 → ⑦ 首页叙事与视觉打磨。

## 九、如何向 AI 描述清楚这个产品

### 9.1 固定上下文包（每次让 AI 干活前一起喂）

1. 本 PRD 的「一 产品概览」+「二 核心流程」（约 300 字，让 AI 知道产品是什么）。
2. 一条真实的风险规则样例（含全部字段，让 AI 模仿数据结构）。
3. 对应任务的验收标准编号（如「本次改动要过 A06、A10」）。
4. 红线声明（见 9.3）。

### 9.2 让 AI 生成结构化输出的提示词模板

```
角色：你是租房合同审查引擎，只依据我提供的合同原文工作。
输入：合同正文（<text>）。
任务：按规则库逐条匹配，输出 JSON 数组，每条包含：
  id / title / level(high|medium|low) / evidence(原文逐字引用) /
  explain(大白话) / suggestion(替代条款) / negotiation(谈判话术)
约束：
  1. evidence 必须是原文的逐字子串，找不到就丢弃该条；
  2. 不臆造合同里不存在的条款、金额、日期；
  3. 只输出 JSON，不要解释。
自检：输出前逐条验证 evidence 是否能在原文中找到。
```

### 9.3 三条红线（写进所有提示词）

1. **不编造证据**：任何结论必须指向可回查的原文，找不到就不出这条结论。
2. **不覆盖确定性规则**：风险评分、证据校验等代码算出的结果为准，AI 话术只做包装不做改判。
3. **不假装成功**：模型失败就明说降级，禁止编一段「看起来像结果」的回复。
