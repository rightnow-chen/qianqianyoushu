# 签前有数

签前有数是一个面向刚毕业、第一次租房人群的 AI 签约决策助手，当前交付形态是 Web 单页应用。它聚焦一个核心问题：**帮用户判断「这套房到底该不该签」**——把租房合同审查、风险证据高亮、大白话解释、谈判话术和修订合同生成，整合成一条「看懂合同 → 采纳改法 → 带着结论去谈」的审查闭环。

## 关于本项目

这是我在求职 AI 产品经理岗位期间，基于一个开源租房合同审查项目进行二次改造的作品集项目。原项目是一个「合同审查 + 验房 + 退租证据包 + 补贴匹配」的全流程工具箱，而我的改造方向是**从「风险清单」收敛到「签约决策」**——用户真正想解决的不是「合同里有多少坑」，而是「我到底该不该签这套房」。

围绕这个目标，我做的核心改动：

1. **砍掉与签约决策无关的模块**（入住验房、退租证据包、城市补贴匹配），把产品主线收窄到「合同 → 决策」一条链路，避免功能堆砌稀释核心价值。
2. **坚持「无证据不出结论」**：每条风险结论强制绑定合同原文，杜绝 AI「看起来专业、其实瞎编」。
3. **把风险清单翻译成可行动的语言**：每条风险都附大白话解释、谈判话术和替代条款，支持一键采纳生成修订版合同，让输出从「哪些条款有坑」变成「怎么改、怎么谈」。

## 体验入口

- Web 版：`npm run dev` 后访问 Vite 本地地址，即可演示完整「合同审查 → 签约决策」流程。
- 适用人群：刚毕业、第一次在异地租房的人群。

## 推荐演示路径

1. 进入首页，点击「立即体验合同审查」，或载入一份演示合同。
2. 粘贴合同正文，或导入 TXT、MD、DOCX、PDF、合同图片，点击「开始审查」。
3. 查看风险清单：每条风险都绑定合同原文证据、风险等级、大白话解释和谈判建议。
4. 采纳修改建议，导出「修订合同」DOCX，验证二次复查后风险是否消除。
5. 打开「AI 助手」，追问「押金条款怎么和房东谈」，验证联网失败时本地知识库兜底可用。

## 项目亮点

- 签约决策导向：不只列风险，而是给出整体风险评分、分级结论、大白话解释和谈判话术，让用户带着结论去和房东谈。
- 证据绑定：每条风险都关联合同原文，不凭空制造风险结论。
- 租客视角：默认围绕押金、涨租、维修、违约、入户、管辖等真实租房痛点做严格审查。
- 可行动输出：不仅提示「有风险」，还给出大白话解释、谈判话术、替代条款和 DOCX 报告。
- 演示不断线：模型接口不可用时，自动切换本地租房风险规则和知识库兜底。

## 运行

```bash
npm install
npm run dev
```

默认访问 Vite 输出的本地地址。

如果要使用真实大模型接口，推荐同时启动后端代理：

```bash
copy .env.example .env
npm run dev:api
npm run dev
```

也可以一条命令同时启动前端和代理：

```bash
npm run dev:full
```

后端代理默认监听 `http://localhost:8787`，Vite 会把 `/api` 转发到代理服务。真实密钥放在后端环境变量里：

- `AI_PROXY_API_KEY`：通用兜底 API Key
- `DEEPSEEK_API_KEY`：DeepSeek
- `DASHSCOPE_API_KEY`：通义千问
- `ZHIPU_API_KEY`：智谱 GLM
- `MOONSHOT_API_KEY`：Moonshot
- `ARK_API_KEY`：火山方舟 / 豆包
- `HUNYUAN_API_KEY`：腾讯混元
- `AI_PROXY_BASE_URL` / `AI_PROXY_MODEL`：可选强制覆盖项，一般保持空，让前端服务商预设自动匹配

### 单端口模式：`npm start`

`npm run build` 之后直接 `npm start`，一个端口（默认 8787）同时提供页面和接口，拍照 OCR、AI 审查都能用，不用再开 Vite：

```bash
npm run build
npm start          # http://localhost:8787
```

两个坑已经踩过并修掉，改这块代码前先看一眼：

- **CORS 必须放行自己的 origin。** vite 给 `script` / `link` 加了 `crossorigin`，浏览器会把静态资源请求也当成 CORS 请求。如果 `allowedOrigins` 里只有 `localhost:5173`，同端口访问时样式和脚本全被拦（页面白、控制台 500）。`server/config.mjs` 现在会自动把 `http://localhost:<port>` 和 `http://127.0.0.1:<port>` 加进去。
- **OCR worker 的异步错误不能让它炸进程。** tesseract 的 worker 出错时会调用 `createWorker` 的 `errorHandler`；不传它，库会在 `process.nextTick` 里直接 throw，整个 Node 进程退出——症状是「识别成功一次，网站就再也打不开」。`recognizeImageOffline` 现在把 `errorHandler` 和 `terminate` 的异常都接住，`tests/unit/ocr-worker.test.mjs` 钉死。
- `/api/ai/smoke` 是自检入口（不消耗额度）：返回 AI 与 OCR 两条链路的连通情况，排查「AI 用不了」先打它。

## 当前能力

- 首页总览：展示项目定位、完整演示路线（含 90 秒快速路线）和审查流程教程，一键进入合同审查。
- 租房审查：支持粘贴合同正文、载入多个演示合同模板，并可导入 TXT、MD、DOCX、PDF 和图片 OCR 合同，按租客视角识别押金、涨租、维修、解除、入户、管辖、格式条款等风险。
- 证据绑定：每条风险都关联合同原文片段，点击可回查出处，不凭空制造风险结论。
- 修改采纳：逐条或全部采纳风险修改建议，已采纳卡片会从待处理列表消失，并生成修订版合同草案和修改对比。
- 二次复查：采纳后的合同会直接写回编辑区，下载优化合同后再审查时可验证旧风险是否已经被改掉。
- 租房小助手：通过“AI 助手”打开，结合当前模块、合同风险、谈判进度和费用信息，帮助用户判断下一步。
- AI 回复训练：内置风险审查、证据核验、依据引用、回复排版等技能，要求输出更专业、克制、少符号、可执行的回复。
- 知识库：本地规则与 `/api/rag/search` 轻量检索共同参与 AI 上下文，模型不可用时会切换到本地知识库兜底回复。
- DOCX 导出：租房解读报告和优化合同均可导出为 `.docx`，便于用户继续编辑和留档。
- 本地状态：审查历史、AI 配置和使用反馈保存在浏览器本地，支持一键导出全部数据和清除全部痕迹。

## 左侧显示的合同内容（确认页 + 结果页）

两页的规则不一样，别混着改：

| 来源 | 确认页 | 结果页 |
| --- | --- | --- |
| PDF | pdf.js 渲染成 canvas，可翻页 | 同左，再加透明文本层做高亮定位 |
| Word | docx-preview 还原真排版（字体 / 缩进 / 表格 / 分页） | 同左 |
| 图片（拍照） | 原图 + OCR 文字两档，用来核对识别得准不准 | **只给排过版的文字**，不摆照片 |
| TXT / 粘贴 | 按条款层级重排的纯文本 | 同左 |

图片在结果页不显示照片是产品决定：照片没法句子级定位，也不帮人读合同，用户要读的是识别出来的字。确认页保留原图，是因为那一刻的任务是**核对 OCR 准不准**，需要两边对照。

Word 不用 Office Online / WPS WebOffice 的原因：那两套都要求文件有公网可访问的 HTTPS 地址（等于把合同先交给第三方），还要后端签名和商业授权。「不存储原文」是这个产品的底线，所以走纯前端渲染。代价是字体依赖本机（Windows 自带宋体/仿宋，macOS 会 fallback）。

渲染失败的极少数情况（加密、损坏、`.doc` 改名成 `.docx`）会退回按标题/段落拍平的文本，至少让人能看到字。

### 结果页左栏（`screens/workbench/OriginalDoc.jsx`）

只有 PDF / Word 走原件（`ContractPane.jsx` 的 `hasOriginal`），其余走重排的纸（`PaperDoc.jsx`：演示数据、纯文本、拍照）。

PDF 走 `preparePage()`：先给每一页搭一个空白 canvas **和透明的文本层**，返回的 `draw()` 稍后补画面。分开的原因是一份 22 页的合同如果「画完一页再画下一页」，要等五六秒才有完整文字；文本层是纯 DOM，建起来快，所以先让定位/高亮/选中可用，canvas 再一页页补。**只有 canvas 的话，画得再像也只是张图，点哪儿都定位不了。**

风险句的高亮用 **CSS Custom Highlight API**（`features/docHighlight.js`），不往 DOM 里插 `<span>`：PDF 文本层的 span 全是绝对定位的、docx 的表格分页也是库自己排的，插节点会把版式打乱。做法是把容器里的可见文字压成「无空白字符串 + 每个字符落在哪个文本节点的第几位」，匹配到之后映射回 `Range` 交给浏览器画。

- `::highlight(risk-must / risk-check / risk-note)` 三档淡色底，`risk-active` 是当前这条（加深），样式在 `app.css`。
- 点右侧「定位至原文」→ `scrollRangeIntoCenter()` 滚到视野正中。
- 点原件上标过色的句子 → 取光标落点，看它落在哪个已登记的 `Range` 里，跳到那条风险；正在框选文字时不触发。
- 扫描件（PDF 没有文字层）不做高亮，顶部标「扫描件 · 无文字层」，右侧照样有原句可对照。
