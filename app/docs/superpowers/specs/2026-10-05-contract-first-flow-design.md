# 合同先行的签约判断流程设计

## 已确认的目标

主要用户已经拿到租房合同，想尽快知道这套房现在能不能签、不能签的原因，以及下一步该做什么。保留现有 Web 版的五个入口和主要组件，优先修顺导航、页面职责和判断闭环，不新建业务页面或后端能力。

## 页面结构

侧边栏仍有五个入口，分为两组，不把它们画成五个连续步骤：

| 分组 | 入口 | 职责 |
| --- | --- | --- |
| 主流程 | 审合同 | 导入合同、核对原文、查看有证据的风险 |
| 主流程 | 签约判断（原“签约建议”） | 给出当前判断、关键原因和唯一的下一步动作；谈判后回来复核 |
| 主流程 | 谈判台 | 处理待解决条款、记录回应、把谈妥内容写进合同 |
| 辅助 | 房源与预算（原“填需求”） | 补充预算、租金、押金、通勤等判断资料 |
| 辅助 | AI 助手 | 在任意阶段解释问题，不作为必经步骤 |

首页主要按钮直接进入“审合同”。现有旧链接兼容逻辑保留，但首页和演示路线不能继续把内部导航目标写成旧的 `review`。

## 用户路径

1. 用户导入或粘贴自己的合同，完成审查；演示合同仅在用户主动载入时使用，不参与真实房源的判断。
2. “审合同”展示原文与风险，主按钮进入“签约判断”。用户可先只看合同风险；缺少预算或月租时，判断页明确显示待补信息并提供直达入口，不让用户在五个 tab 里猜下一步。
3. “签约判断”先给初步判断。若预算明显不合适，可以在此停止；若有需要谈或核实的问题，按钮带着具体问题进入“谈判台”；没有待谈问题时可跳过谈判。
4. “谈判台”区分待谈、谈中、已谈妥、已写入合同。仅口头谈妥不能视为已完成。落稿后提供“复查合同并返回签约判断”的明确出口。
5. 对最新合同复查后，“签约判断”更新结论；如果仍有关键问题，继续处理，否则展示可考虑签约的判断及未解决的注意事项。

这是一条可回访的流程，不使用暗示四页必须依次完成的固定步骤条。页面上的进度提示改为当前事实，例如“合同已审”“2 项待处理”“1 项已写入合同”。

## 各页布局

### 审合同

页首放合同导入与审查动作。完成后先看到风险概览，再看现有的“左侧合同原文、右侧风险清单”。风险卡保留原文定位、解释和去谈判台的单条入口。页尾保留修订草案与导出作为次级区域；审查完成后的主按钮是“查看签约判断”。

### 签约判断

首屏依次展示：当前判断及“初步/复核”标识、最多三条决定性原因、一个随状态变化的主按钮。下方展示待处理事项及其状态，再折叠显示费用测算和信息来源。可复制的“问房东的问题”归入待处理事项，可从这里进入谈判台使用，不再像最终签字后的附加任务。

判断页只要求预算和月租等直接影响成本判断的核心信息；计划入住日期等未填写项显示为待核实，不阻止用户先看到合同风险和初步判断。完整签约判断要以用户自己的当前合同已审查为前提。零风险同样算“已审查”，未上传合同不能显示“可以签”。

### 谈判台

保留现有左侧待谈清单、中间话术对话、右侧条款档案。页面顶部显示待谈、已谈妥、已写入合同的数量；条款详情明确显示房东回应与是否落稿。落稿后显示修订结果摘要、查看合同入口，以及“复查合同并返回签约判断”主按钮。用户无法谈妥时，该条保持未解决，判断页应据此继续提示风险。

### 房源与预算、AI 助手

房源与预算页复用现有表单，把预算、月租和与签约成本直接相关的项目放在前面，其他字段继续折叠。用户从判断页来补信息后能一键返回判断页。AI 助手保留现有对话页和业务上下文，但在导航中归入辅助工具，不参加主流程进度。

## 判断与数据规则

- 审查状态与风险数量分开保存：检查过且发现零条风险，是“已审查”，不是“尚未审查”。
- 判断针对当前合同版本。修改合同后，旧结论标为待复核；复查最新版本后才更新为复核判断。
- “已谈妥”表示沟通结果；“已写入合同”表示文字已落稿。两者不能混用，也不能凭聊天记录自动消除合同风险。
- 判断页的主动作按优先级选择：补关键资料、处理高风险、把谈妥内容落稿、复查新合同。存在待处理事项时只突出一个主动作；已可给出复核判断时展示结论和依据，不再强迫用户继续跳页。
- 费用未知或信息来源仅为口头承诺时，判断页明确提示不确定性，不给出无条件的“可以签”。

## 验收场景

1. 首次进入且已有合同：首页一键到合同导入，审完能到初步判断。
2. 已审合同但零风险：正确显示“合同已审”，不会永远停留在初步状态。
3. 没有用户合同：即使预算与月租已填，也不能显示“可以签”。
4. 高风险未谈：判断页引导到对应条款；谈妥但未落稿时仍提示待写入合同。
5. 落稿并复查：从谈判台回到最新合同，再回到判断页，结论依据最新风险变化。
6. 没有待谈问题：用户可从判断页完成核对，不被迫进入谈判台。
7. 缺预算或月租：可看到合同风险与待补提示，补完可直接回到判断页。

## 实施边界

复用现有 `AppSidebar`、`ReviewInputPanel`、`DecisionResult`、`NegotiationDesk`、`DecisionInputForms` 和 AI 对话组件。主要工作是导航分组、页面主按钮、判断状态与少量信息位置调整；不重写合同识别、谈判 AI 或导出服务。
